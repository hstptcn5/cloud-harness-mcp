# ChatGPT Image → CloudHarness → GitHub: handoff contract

**Status:** Receiving-side implementation; end-to-end automatic ChatGPT Image transfer **has not been verified or enabled**. This document is a deploy/review checklist, not permission to access ChatGPT conversations.

## What exists today

CloudHarness supports an authenticated `asset_import` MCP operation that accepts PNG/JPEG/WebP/ZIP base64, verifies the signature/extension and optional SHA-256, and writes a new workspace file (maximum 6,000,000 decoded bytes). The `image_inspect` operation reports format, dimensions and digest. `workspace_finalize` stages, commits and pushes only explicitly chosen asset paths.

This branch adds an authenticated **per-operation HTTP size exception** so the normal 1 MiB `MAX_BODY_BYTES` cap does not reject typical ChatGPT-generated PNG images before `asset_import` can inspect them. All other MCP tool calls retain the original cap. No arbitrary URL fetch was added.

## Desired no-download agent flow

Only if the ChatGPT client can **access the generated image bytes and invoke** the CloudHarness `asset_import` tool:

1. User requests an image and explicitly authorizes import into a named repository/destination. Do not guess a repository, choose an existing workspace or branch without inspection, or auto-push unreviewed sources.
2. ChatGPT generates an image; a **client-side attachment bridge** must expose those exact bytes to the tool caller. The CloudHarness server cannot read ChatGPT's private asset store by URL, title or image ID and must never be asked to scrape an inaccessible private URL.
3. Open CloudHarness workspace on an authorized **feature branch**. Read repository skill and run `git_status` to protect unknown changes.
4. With actual bytes, calculate SHA-256, choose a deterministic, non-overwriting file name and call `asset_import` using `{ workspaceId, path, kind, contentBase64, expectedSha256, overwrite: false }`. Do not pass a made-up base64 value or metadata as image content. The invoking client must enforce its own media and tool-call size limits.
5. Call `image_inspect` with `includeBase64: false` and compare returned file digest to source. Do not mistake exact bytes/dimensions validation for artistic QA. For game sprites, run the SpriteForge or Unity pipeline separately.
6. After an explicit repository/branch/asset review, use `workspace_finalize` with `all: false` and only the approved image path(s), `push: true`. Keep a Draft PR for review when the image is a source reference.
7. Report the repository URL, exact path, commit, hash, and any unverified steps. Never merge or deploy automatically.

## Current missing integration

- The current ChatGPT-connected CloudHarness tool list **does not expose** `asset_import` or `image_inspect`, even though the source repository defines both. The connected MCP app/registration must be updated and refreshed before invoking the tools in this chat.
- ChatGPT Image generation by itself does **not** send the generated image's binary data to a connected MCP service. An authorized, platform-supported attachment/artifact bridge must provide the image bytes to the invoking client. No browser download workaround is implemented here, and merely enlarging MCP request limits does not solve that missing permission/transport.
- Infrastructure may still limit request size (reverse proxy/CDN/client). This branch updates the nginx config template to allow 9 MiB **only on /mcp, /mcp/workspaces/, /mcp-api-key**, while preserving the smaller /mcp-gateway cap. Existing deployed proxy configuration will not update itself; it needs reviewed release/deployment. The API still requires authentication and rejects oversized non-asset commands. `/mcp-gateway` and other JSON actions must not receive a broad limit increase.
- Since the connector currently lacks media payload access, **the complete zero-click flow remains BLOCKED** until the platform and refreshed connector both support it.

- Do not deploy, expand OAuth scopes, enable unsafe URL fetches, or alter existing user assets without authorization.
